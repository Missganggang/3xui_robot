## Cloudflare 管理验收

1. 所有登录客户都能看到“域名与 DNS”；普通客户看不到 Account ID、Token 配置和全账号域名列表，直接请求管理员配置或授权接口返回拒绝访问。管理员可保存 Account ID 与最小权限 Token，并在客户列表为每位客户多选分配域名。
2. 使用专门的测试账号或测试域名验证真实 Cloudflare 连接。Token 不在读取接口、页面、日志或错误中回显；已配置时留空保留 Token，权限不足或账号不匹配时明确报错，且不覆盖原配置。
3. 新客户和已有客户默认没有域名授权，显示明确空态；分配后仅返回授权域名，移除授权后不能继续读写该域名。管理员仍可管理配置账号内的全部可见域名，不能使用非当前 Cloudflare 账号的域名或记录编号越权操作。
4. 域名列表可搜索并读取全部分页记录；A / AAAA / CNAME / TXT / MX 支持增改删，其他类型只有“查看”。新增默认为灰云；TXT 保留文本、引号与换行；MX 优先级、TTL 以及橙灰云状态正确保存。删除确认显示域名、类型、名称和内容，取消不发出删除请求。
5. 会话过期或退出后清除页面中的 Token 输入、域名、记录及打开的编辑窗口；连接失败、权限错误与限流均提供清楚反馈，不显示操作成功。
6. 用测试域名灰云 A / AAAA 解析到验收 VPS 后再部署，确认现有 HTTP-01 与目标 IP 检查继续生效。Cloudflare 页面不会自动修改客户部署域名。
7. 名称输入使用相对前缀和固定当前域名后缀，实时预览完整名称；分别检查 `aaa`、`@` 和多级前缀 `foo.bar`，编辑完整已有名称时正确还原前缀。客户不能通过更换前缀操作授权域名之外的名称。
8. 每个域名显示 `N/100` 记录数量。99 条时可以新增，100 条时禁用新增并说明原因，后端拦截绕过页面或并发提交；100 条及原本超过 100 条时仍可编辑和删除已有记录，降到 100 条以下后恢复新增。

## 新装验收

1. 客户账号不能查看其他客户任务、结果或日志；停用/重置后旧会话无效。
2. SSH 密码错误、指纹库损坏或无法写入、无 root 权限、非支持系统，均给出明确错误。分别用普通客户和管理员发起安装及迁移：首次公钥自动记录，主机指纹变化时使用本次握手的真实公钥，仅原子更新对应 IP 与 SSH 端口并继续执行，不出现手动确认或再次输入密码的步骤；日志包含旧、新 SHA-256 指纹。内网、回环和云元数据目标仍被拒绝。
3. 域名未解析/解析错误、80 被占用、面板端口被占用、云安全组未放行，给出可处理的失败原因。模拟网站系统 DNS 缓存与公网不同：只有两家独立 DoH 返回的完整 A / AAAA 地址集合一致且全部对应任务目标 IP 时才继续；存在旧 AAAA、其他 IP、两家结果不一致或公网核验失败时停止，失败日志列出本任务域名、目标 IP 和实际解析 IP。
4. 两个版本分别安装，核对实际版本；执行器不阻塞在交互输入，也不误报下载成功。
5. HTTPS 证书对域名有效，完整路径可访问，`qqqzzz / qqqzzz` 实际登录成功。面板绑定的证书和私钥分别为 `/root/cert/<域名>/fullchain.pem`、`/root/cert/<域名>/privkey.pem`；例如示例域名 `panel.example.com` 使用 `/root/cert/panel.example.com/` 目录。
6. 确认 ACME 续期定时任务存在，续期写入上述同一证书和私钥路径，并让 x-ui 重新加载证书；使用 ACME staging 单独验证续期，避免消耗正式签发额度。
7. BBR 当前有效且重启后仍有效；不支持 BBR 的内核有明确失败提示。

## 迁移验收

1. 使用两个版本各自真实导出的数据库，包含多个入站、客户、流量、到期时间及禁用状态；迁移前后核对。
2. 备份在安装前生成；现有目标的原版本程序、数据库、服务配置及本次域名原有的 `/root/cert/<域名>/` 证书可以恢复，其他域名证书不受影响。
3. 损坏 SQLite、伪装扩展名、超大文件、不同版本和非标准视图/触发器被拒绝。
4. 文件通过 SFTP 上传；校验哈希；停止服务后原子替换 `/etc/x-ui/x-ui.db`；旧 WAL 不混入。
5. 临时安装完成后才导入数据库；旧账号、密码、端口、路径和入站业务数据全部保留，只有域名、监听 IP 和面板证书路径适配目标服务器。面板证书绑定与 ACME 续期均使用 `/root/cert/<域名>/fullchain.pem` 和 `/root/cert/<域名>/privkey.pem`，核对续期重新加载后仍使用相同路径。最终交付地址确实使用旧端口和旧路径。
6. 原两步验证不重置，原验证器仍有效；结果明确提示使用原账号登录，后台不读取旧密码或宣称已验证旧账号登录。
7. 带外部证书或订阅地址的数据库给出依赖提示，不能把“面板恢复”写成“所有节点已可用”。
8. 重启前通过 x-ui、HTTPS、BBR、原端口/路径及数据库数量检查后，立即显示迁移完成和最终面板地址，再安排整机重启。结果 `reboot_scheduled=true` 时明确提示已安排重启及面板会暂时不可访问；未确认调度时为 `false`，明确提示手动重启。两种情况均为 `reboot_verified=false`，不等待 SSH 回连或声明重启后验收通过。由客户使用原账号和验证器核对实际登录。
9. 源版本为客户声明，提示不把表名当作精确版本证明。2.9.4 备份分别覆盖无残留表、仅空 `clients`、仅空 `client_inbounds` 和两表均空，仍按入站 JSON 核对客户数；任一表有记录均应在远程修改前拒绝并说明保全风险，不能因另一表缺失或为空而漏检。3.4.2 缺少 `clients` 时明确要求核对原版本与完整备份，不自动转换布局，也不引导客户随意更改版本选择绕过校验。

## 故障验收

1. 同一目标重复提交不会产生两个活动任务；不同服务器可并行。历史因旧指纹规则失败的任务保留失败记录，不自动重试；用户重新填写 SSH 密码后可重试，前端不要求点击信任指纹，新的执行过程自动处理指纹变化并记录日志。
2. 迁移完成前的中途断网、下载失败、证书失败、导入失败或验收失败均不会误报成功。重启调度未确认时仍返回已完成迁移的地址，同时明确提示手动重启，不声称已实际重启。
3. 迁移完成前失败时，回滚恢复原数据库、旧程序和服务；回滚失败时日志明确，并保留备份。安排重启后不等待恢复，也不因重启后的暂时不可达而回滚。
4. 网站重启后，已运行的任务标为中断而不盲目重放；客户需重新提供 SSH 密码才能重试。
5. 浏览器刷新和关闭不终止后台任务；日志、数据库和 API 不暴露 SSH 密码。
6. 上传文件到期自动清理，运行中的上传不会被清理；任务完成后加密 SSH 密码被删除。
7. 重试面板显示旧任务实际沿用的域名和服务器 IP；修改“新建任务”的域名后再打开旧任务重试，摘要和请求仍使用旧目标。需要更换目标时必须创建新任务。

## 发布与资料检查

1. 公开仓库、示例配置与验收记录中没有 `.env`、Token、私钥、真实客户数据库、上传文件、备份或生产日志；实际 IP、域名与账户信息使用示例值替换。
2. Cloudflare Token 仅在管理员后台输入，加密存入本地网站数据库，不回显。使用仅包含所需区域的 Zone:Read、DNS:Edit 权限，移除非必要资源范围。
3. 网站密钥与数据通过独立安全渠道备份；密钥不随源码发布。恢复测试使用原 `APP_SECRET`，核对 Token 可解密及上传绝对路径正确，不提交恢复后的数据库。
