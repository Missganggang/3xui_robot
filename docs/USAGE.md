# 管理员与客户使用说明

本文中的 `example.com`、`panel.example.com` 均为示例域名。网站登录账号与目标 3x-ui 面板账号相互独立。

## 管理员流程

1. 按 [README](../README.md#本地运行) 或 [部署维护文档](../deploy/OPERATIONS.md) 启动网站，通过 CLI 交互创建管理员，无默认网站账号密码。
2. 登录后打开“客户管理”，创建客户用户名和初始密码，通过受信任渠道交付。可启用、停用客户；客户仅能查看自己的任务。
3. 如需客户管理 DNS，在“域名与 DNS”连接 Cloudflare，再回到客户列表点击“分配域名”，勾选客户可操作的域名并保存。
4. 检查执行器状态、目标服务器准备事项及测试环境验收结果，再允许客户提交安装/迁移任务。

客户没有隐式域名授权，新账号和原有账号默认均为空。全部取消勾选后保存即撤销该客户的域名授权。管理员可以管理当前 Cloudflare 账号中 Token 可见的域名，客户只能操作明确分配给自己的域名。

## Cloudflare 连接与域名授权

在 Cloudflare 创建受限 **API Token**，最小权限为：

| 资源 | 权限 |
| --- | --- |
| Zone / 区域 | Zone / 区域：Read / 读取 |
| Zone / 区域 | DNS：Edit / 编辑 |

资源范围只包含准备交给本工作台管理的区域。无需使用 Global API Key，也不要授予无关账户权限。管理员在网站后台输入对应的 **Account ID** 和 Token，点击“保存并验证”；只显示当前账号中 Token 有权读取的域名。Token 的 Cloudflare 权限和网站里的客户域名授权需同时满足。

Token 只通过登录后的后台表单输入，不放在 Git、`.env.example`、部署脚本、截图或日志中。应用将其加密保存到本地网站数据库 `DATA_DIR/console.sqlite3`，不会通过配置读取接口或页面回显。已配置后留空会保留原 Token，填写新值则替换；只有验证成功才保存。数据备份和迁移必须保留原 `APP_SECRET`，否则无法解密已保存 Token。更换 Cloudflare 账号时，客户域名授权会清空，需要重新分配。

所有登录用户都有“域名与 DNS”入口。客户没有授权时显示空态，看不到 Account ID、Token 配置及账号下其他域名。客户不能调用管理员配置和域名分配接口。

## DNS 记录操作

选择有权限的域名后可查看解析记录。A / AAAA / CNAME / TXT / MX 支持添加、编辑和删除，其他类型只读展示；删除前会显示域名、类型、名称和内容供确认。变更会直接同步到 Cloudflare。

- 记录名称只填相对前缀。当前域名为 `example.com` 时，填写 `aaa` 预览 `aaa.example.com`；`@` 表示根域名，`foo.bar` 表示 `foo.bar.example.com`。编辑已有完整名称时自动还原前缀。
- 新记录默认仅 DNS（灰云）。只有 A / AAAA / CNAME 可开启代理；部署面板所用域名应保持灰云。
- TTL 支持自动或 60–86400 秒；代理记录由 Cloudflare 使用自动 TTL。MX 需要 0–65535 的优先级，TXT 保留原始内容、引号与换行。
- 数量显示 `N/100`。达到 100 条后停止新增，已有记录仍可编辑、删除；原本超过 100 条的域名也可维护，降至 100 条以下后恢复新增。后端对并发新增也执行上限检查。

DNS 管理不会自动把部署任务的域名指向目标服务器。客户必须在部署前核对记录和代理状态。

## 客户准备事项

- 提供有权管理的公网 Ubuntu / Debian 服务器、SSH 端口及 root 密码，目标上 `python3` 可用，使用 systemd 和默认 SQLite 安装。网站拒绝内网、回环和云元数据地址。
- 准备面板完整域名，例如 `panel.example.com`。只填域名，不含协议、端口或路径；所有 A / AAAA 记录必须仅指向本次填写的目标服务器 IP，清理旧地址并关闭 CDN/橙云代理。
- 公网 TCP 80 需要空闲且放行，用于 HTTP-01 证书申请与续期。最终面板端口也必须放行；新装为随机或自定义端口，迁移为旧数据库中的原端口。应用不会关闭防火墙或修改云安全组。
- 目标服务器能下载官方 GitHub 发布文件、系统软件包与 ACME 工具，磁盘空间足够，内核支持 BBR。
- 目标已有 3x-ui 时，明确勾选允许备份后覆盖；否则会在修改前停止。

网站先检查系统 DNS。系统解析失败或与目标不符时，会并行查询 AliDNS、DNSPod 的 A 和 AAAA；只有两家的完整地址集合一致且均仅对应目标 IP 才接受。两源不一致、仍有其他地址或任一家族核验失败时停止，不会只因一条 A 记录命中就忽略旧 AAAA。日志列出当前任务域名、目标 IP、系统与公网 DNS 的实际结果，便于排查传播或系统缓存问题。

## 全新部署

1. 客户登录后点击“新建任务”，选择“全新部署”。
2. 填写服务器 IP、SSH 端口、root 密码，选择 v2.9.4 或 v3.4.2，填写绑定域名。
3. 默认随机分配面板端口；需要固定端口时勾选自定义。端口不得与 SSH 或证书验证端口 80 冲突。
4. 提交后在任务详情查看环境检查、备份、安装、证书、BBR 和访问验收日志。关闭浏览器不终止后台任务。
5. 检查通过后返回带域名、端口和随机路径的 HTTPS 地址，新面板用户名和密码均为 `qqqzzz`。交付后请及时修改默认凭据。

面板证书固定为 `/root/cert/<域名>/fullchain.pem`、`/root/cert/<域名>/privkey.pem`，例如 `/root/cert/panel.example.com/`。ACME 自动续期写入相同路径并重新加载 x-ui。

SSH 握手会记录首次主机公钥，发现指纹变化时自动更新对应 IP、SSH 端口的记录并继续，任务日志保存旧、新 SHA-256 指纹。此行为不要求客户手动确认；如果密码错误、指纹库损坏或无法写入，会明确失败。普通客户和管理员适用同一规则。

## 同版本迁移

1. 从旧面板导出完整 `x-ui.db`，或停止旧服务后复制。不要直接复制正在写入的 SQLite，以免遗漏 WAL 中的数据；文件上限 50 MiB。
2. 新建任务并选择“数据迁移”，填写新服务器和域名，源、目标版本必须相同：仅支持 2.9.4 → 2.9.4、3.4.2 → 3.4.2。
3. 上传数据库。默认随机端口或自定义端口只用于临时安装；恢复后最终端口、入口路径来自旧数据库。
4. 程序先安装再导入，校验上传哈希，停止服务后原子替换 `/etc/x-ui/x-ui.db`，避免旧 WAL 混入。只适配新域名、证书路径和监听地址。
5. 在重启前完成 HTTPS、服务、BBR、原端口/路径与数据库数量检查，返回最终地址，再安排整机重启。重启期间请稍后访问。

迁移保留旧账号、密码、双重验证、节点和业务数据。客户用原账号、原密码及原验证器登录；后台不读取旧密码，不宣称已验证原账号登录。缺少端口或路径设置时，按所支持版本的默认值 `2053`、`/` 读取并提示。

数据库不包含旧证书、私钥、自定义脚本或 geofile。节点证书路径、订阅域名、旧 IP、入站端口和云安全组需要单独核对；面板迁移成功不代表每个节点均已完成真实连通测试。

结果区分“已安排服务器重启”和“自动重启未确认、需要手动核对”。应用不等待 SSH 回连或重启后的验收，不会把调度成功写成重启完成。迁移完成前失败会尝试恢复原程序、服务和数据库；备份在目标 `/var/backups/3xui-web/<任务编号>/`。安排重启后不因暂时无法访问而自动回滚。

## 失败、重试与执行器状态

先阅读失败原因和当前任务的实际域名、服务器 IP。历史任务“重新发起”只更新本次提供的 SSH 密码，沿用原域名、服务器及其他任务配置；修改“新建任务”表单不会修改旧任务。需要更换目标或配置时创建新任务。

执行器不可用时，页面会显示原因并拒绝新建/重试。网站进程重启后，已运行任务标为中断而不盲目重复执行；应先核对远程状态和备份。已结束任务的上传文件默认保留 24 小时，超期清理后不能直接用旧文件重试迁移，需重新上传创建任务。

更多环境与故障检查见 [验收清单](acceptance.md)。
